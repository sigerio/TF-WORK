# 三机通信方式与软件设计整理

版本：V1.13　日期：2026-11-03。本文整理 `xj_jc`（主控）、`wether`（气象分发板）、`sun_control`（太阳能/电机分发板）三个 GD32F103 工程之间的通信关系与共同设计思路，作为后续协同开发的依据。本轮已更新 `xj_jc/master` 的 MT80 与三合一气象协议，并同步 `wether/master` 的三合一下游串口配置及 `sun_control/master` 的 MT80 双向地址转换；三端软件适配已完成，实机联调尚待验证。IEC104 接口规范为 V3.3（文档修订 R3），保留协议基础与收发机制，按系统功能组织点表；对应点表已接入主控固件，分发板及硬件联调边界见后文。

## 1. 系统拓扑

```text
上位机（主站）
  │  IEC104 APDU，USART1 串行字节流承载（非 TCP）
  ▼
xj_jc 主控板（受控站 / Modbus 主站 / 业务控制）
  │  Modbus RTU 主站
  ├─ USART0 气象总线（同一 485 总线多点挂两块分发板，按地址区分）
  │    ├─► wether 分发板 ──► 三合一气象(0x02, 下游4800) / 水浸(0x04)
  │    │      ▲ 下游两台设备实际站号均为 0x01，各挂独立物理串口
  │    │      └─ 主控单向下发 0xB4 整机故障通知（无应答）
  │    └─► sun_control 分发板 ──► 整机推出电机(0x11) / 立杆升起电机(0x12)
  │           / 太阳板展开电机(0x13) / MT80 太阳能控制器(0x14, 115200)
  │           ▲ 下游电机站号 0x01，MT80 站号 0x0A，各挂独立物理串口
  └─ UART3 空调总线（独立，不经分发板）──► 空调(0x01)
```

核心思想：**主控只面对“上行逻辑地址”，两块分发板做端口级路由 + 地址重打包**。三合一沿用 wether 的 USART2/逻辑地址 0x02。主控总线仍为 9600/8N1，分发板负责下游地址与波特率转换。图示为三端当前软件对应的拓扑，分发板适配状态及联调边界见第 7 节。

## 2. 各工程角色与设计思路

### 2.1 xj_jc 主控（GD32F10x，无 RTOS 自研 OS）

- **上行**：IEC104 服务端（`USER/COMM/iec104/`，分层 port → server → core → app）。串口承载 APDU，保留 APCI/ASDU、序列号 k/w 窗口与确认；扩展了 t2=10 s 周期 S 帧（串口无 TCP 断链可观测）。协议设计稿见 [IEC104 通讯协议规范](../xj_jc/iec104_protocol_spec.md)（V3.3 已实现 75 遥信/108 遥测/60 遥调/31 遥控）；总召包含参数回读。MT80、万融及三合一新增点已接入，三合一共用一个在线点，水浸独立，见第 6.4 节。
- **下行**：Modbus RTU 主站（`USER/COMM/modbus/`）。设备协议层 `devices/modbus_<型号>.c` 只做组帧/解析，不碰队列和串口；`modbus_master` 每条总线独立一问一答，200 ms 超时，共享 16 项发送队列（满时淘汰最旧请求）。轮询 150 ms 推进一项、共 205 项，每组依次读取气象/水浸、MT80、三台电机输入状态。
- **业务**：门/停机坪电机控制（互锁、限位、急停）、辅助输出（指示灯、照明、门加热）、WS2812 灯效（含 P1 安全灯语）、`app_fault` 32 位三级故障汇总。
- **运行模型**：所有硬件/模块初始化集中在 OS 主循环前；中断只搬字节，协议解析和业务全在主循环上下文；周期任务按“定时 → 软事件 → 队列”顺序执行。

### 2.2 wether 气象分发板（FreeRTOS）

纯透明桥，**不解析业务语义**：

- 主控侧（USART1，DMA+IDLE 断帧）只接受地址 `2/3/4/5/0xB4` 的完整 CRC 有效帧；传感器侧只接受地址 `0x01`。
- 请求按地址路由到对应传感器串口并改址 `0x01`；响应按来源串口恢复主控侧地址；双向重算 CRC，功能码和数据原样保留（含异常响应）。
- `0xB4` 故障通知为单向消费：校验后缓存 32 位故障快照（`weather_fault_get()`），由 `run_led_task` 用蜂鸣器复现主控 P1 灯语节奏（急停静音 > 限位冲突双响 > 水浸 500 ms 交替），不应答、不转发。
- RBNE 逐字节收帧 + TIMER2（1 MHz）按 3.5 字符 + 100 µs 余量断帧；FreeRTOS 双任务（comm_rx / comm_queue），20 项队列、`xQueuePeek` + `node_consume_func[data_mark]` 函数指针分发。

### 2.3 sun_control 太阳能/电机分发板（FreeRTOS）

与 wether 同构的透明桥，白名单不同：

- 主控侧只接受 `0x11～0x14`；下游三路电机为 9600、RBNE 收，太阳能口为 115200、DMA 收。三路电机下游站号为 `0x01`；MT80 太阳能口下游站号为 `0x0A`，双向地址转换及接收过滤已同步。
- 地址/路由常量在 `Application/Communication/comm_dispatch.h`，引脚与波特率在 `Platform/Board/board_config.c`。
- **不主动轮询、不生成运动命令、不解析业务寄存器**；主控的分段、轮询和 200 ms 超时由主控负责。
- 已明确移除旧气象地址与 B4 逻辑（B4 只走 wether 板）。

## 4. 分发规则

### 4.1 两块分发板的转发规则

1. **下行（主控→设备）**：只接受上行白名单内地址的完整帧（4~256 字节、CRC 正确）；按地址选定下行串口，三合一、水浸与三路电机改为 `0x01`，MT80 路由改为 `0x0A`，重算 CRC 后转发。功能码、寄存器、数量、数据原样保留。
2. **上行（设备→主控）**：三合一、水浸与三路电机口只接受地址 `0x01` 的完整帧；MT80 来源口只接受 `0x0A`。按**来源串口**恢复对应上行地址，重算 CRC 后从主控口返回。正常响应与异常响应（功能码最高位置 1）都转发。
3. 白名单外地址（含广播 `0x00`）整帧丢弃：不入队、不分配内存、不应答、不转发、不打印日志，也不从包内搜索子报文。
4. 不做业务解析、不主动轮询、不做事务匹配与超时重发；一问一答与 200 ms 超时由主控负责。
5. 两块板挂在主控同一条 USART0 总线上，靠互不重叠的白名单各取所需：wether 收 `2/3/4/5/0xB4`，sun_control 收 `0x11~0x14`，对对方地址的帧静默丢弃。因此**地址表任何调整都必须三端同步**，否则帧会被两边同时丢弃。

### 4.2 地址 → 串口路由表

| 上行地址 | wether 路由 | sun_control 路由 |
|---|---|---|
| 2 | → USART2 三合一（4800，已实现） | 丢弃 |
| 3 | 原雨量逻辑路由移至 UART4 保留闲置，主控不再请求 | 丢弃 |
| 4 | → UART3 水浸 | 丢弃 |
| 5 | 原 USART0 温湿度路由保留，主控不再请求 | 丢弃 |
| 0xB4 | 本地消费（故障缓存→蜂鸣器），不转发、不应答 | 丢弃 |
| 0x11 | 丢弃 | → USART2 整机推出电机 |
| 0x12 | 丢弃 | → UART3 立杆升起电机 |
| 0x13 | 丢弃 | → UART4 太阳板展开电机 |
| 0x14 | 丢弃 | → USART0 MT80（下游改址 0x0A，已实现） |

上行反向：wether 按来源串口恢复 5/2/3/4，sun_control 按来源串口恢复 0x11/0x12/0x13/0x14。

### 4.3 主控侧分发规则

- `modbus_devices` 按设备把请求送入对应总线：三合一气象、水浸、B4、三电机、MT80 均走 USART0 气象总线；空调走 UART3 空调总线。每条总线独立一问一答、200 ms 超时，共享 16 项发送队列（满时淘汰最旧）。
- 150 ms 轮询按“三合一/水浸读取 → MT80 分段读取 → 整机推出状态 → 立杆状态 → 太阳板状态”入队，三电机均读取 FC03/2015/1；状态触发限位停止见第 5.2 节。
- B4 走优先槽：变位即覆盖最新值并置 pending，气象总线当前事务结束后，在限位停止之后、普通请求之前补发；不进等待应答状态。
- RS-485 写操作经软事件转入 Modbus 写接口，不在 IEC104 解析链路中直接发串口。

## 5. 关键通信约定（跨工程必须保持一致）

### 5.1 上行地址分配（主控视角）

| 地址 | 设备 | 所在总线/分发板 |
|---|---|---|
| `0x01` | 空调 | 空调总线（主控直连） |
| `0x02` | 三合一气象 | wether USART2（沿用原风口，4800） |
| `0x03` | 原独立雨量，停止请求 | wether 原路由保留 |
| `0x04` | 水浸 | wether |
| `0x05` | 原独立温湿度，停止请求 | wether 原路由保留 |
| `0x11` / `0x12` / `0x13` | 整机推出 / 立杆升起 / 太阳板展开电机 | sun_control |
| `0x14` | MT80 太阳能控制器 | sun_control（115200，其余 9600） |
| `0xB4` | wether 板故障通知（主控→板，单向） | wether |

下游三合一/水浸/三电机为 `0x01`，MT80 为 `0x0A`。**地址集中定义**：主控在 `modbus_config.h`，wether 在 `comm_dispatch.c`、sun_control 在 `comm_dispatch.h`；改地址必须三处同步。

### 5.2 万融电机命令与物理输入

- `4x-2000`：FC06，线地址 `0x07D0`，值 0/1/2 = 停止/CW（正转）/CCW（反转）；正转=推出/升起/展开。地址基准沿用现有十进制编号，具体机构方向需实机核对。
- `4x-2015`：FC03，线地址 **`0x07DF`**，读取 1 个 16 位寄存器，高字节在前。2026-10-16 用户补充如下，当前按 1=有效、0=无效解释；bit4～15 保留原码，不参与判断。

| 位 | 掩码 | 含义 |
|---|---|---|
| bit0 | `0x0001` | CW 启动按键状态 |
| bit1 | `0x0002` | CW 限位开关状态 |
| bit2 | `0x0004` | CCW 启动按键状态 |
| bit3 | `0x0008` | CCW 限位开关状态 |

控制规则：

1. **物理按键优先**。bit0 或 bit2 有效时，仅使用按键方向判断：bit0+bit1 同时有效发送停止，bit2+bit3 同时有效发送停止。无需存在通讯启动命令；两键同时有效时两个方向分别检查。
2. 检测到物理按键后，清除该电机未发送的通讯运动命令和已记录的旧通讯方向；物理按键有效期间拒绝新的通讯启动命令，停止命令仍可下发。按键释放不恢复旧通讯动作。
3. 两个物理按键均无效时，按最近已交给发送链路的通讯方向判断：CW 遇 bit1 停止，CCW 遇 bit3 停止。仅排队、尚未发送或发送接口拒绝的命令不记录为运动方向。同方向限位有效时拒绝新的通讯启动，允许反方向退出。
4. 限位停止采用每台电机独立待发位，清除该电机普通队列中尚未发送的运动命令，保留停止、读取及其他设备请求。总线空闲后的发送顺序为 **限位停止 → B4 → 普通队列**；不打断已开始的事务。停止不受普通队列满淘汰影响，发送接口拒绝时保留待发。
5. 通讯方向在合法停止回显后清除；若停止回显失败或超时，下次状态读取仍满足条件时再次请求停止。物理按键与对应限位持续有效时，每次有效状态读取都会请求停止，避免按键保持造成重新启动。
6. 仅 CRC、地址、功能码、寄存器数量全部通过校验的状态更新缓存并触发判断。读取失败保留上次有效输入；本次未增加失联自动停机规则。首次读取前没有物理输入缓存，通讯启动仍按现有方式接受。

这些输入用于主控内部限位逻辑；本次不新增 IEC104 遥信/遥测 IOA，原接口不提供三机构运行、到位和在线反馈。停止写入回显只证明通讯命令被应答，不能证明机械已停止。电机编号 1/2/3 与上行站号 `0x11/0x12/0x13` 不同。

限位来自周期读取，正常组内每台约 750 ms 入队一次，轮询尾部跨轮间隔约 1500 ms，实际还受队列、200 ms 事务超时和总线影响；此软件逻辑不具备硬接线限位的即时响应。状态位极性、地址基准和 CW/CCW 机构方向需实机核对。

### 5.3 B4 整机故障通知（主控 → wether，单向）

```text
B4 41 04 D0 D1 D2 D3 CRC低 CRC高      （9 字节，D0..D3 = fault_state.raw 小端内存副本）
```

- 位定义与 `xj_jc/USER/APP/app_fault.h` 固定一致，**后续不得重排**：bit0 急停，bit1/2 门/平台限位冲突，bit3 有效水浸，bit4~11 P2 运行告警，bit12~24 P3 离线/传感器故障。
- 接收端用 `memcpy` 复制到对齐变量；bit3=0 只有在 bit14、bit19 均为 0 时才能解释为有效无水。
- 主控侧用“优先槽 + pending”覆盖最新值，变位即发、周期补发；不进入等待应答、不维护在线位。
- 已知测试帧：全零 `B4 41 04 00 00 00 00 11 DA`；仅急停 `B4 41 04 01 00 00 00 10 26`；字节序 `B4 41 04 78 56 34 12 7F A7`。

### 5.4 共同工程约定

- 一问一答；200 ms 是主控事务预算，不是分发板断帧时间。
- 整帧校验：长度 4~256 字节 + CRC；非白名单地址在分配内存/入队前整帧丢弃，不搜索帧内子报文。
- 485 方向：高电平发送；发送前等待 `RS485_TX_SETUP_US`（默认 100 µs）方向建立时间，以实测波形调校。
- 均 8N1；485 上电默认接收。
- RTT 日志格式统一 `[ms] [UARTn RX/TX len=N] XX ...`；只打印通过校验的帧；缓冲不足整条跳过。
- FWDGT 看门狗由空闲任务喂狗（标称 2 s）。
- 4G 将来与主控侧 USART1 复用，三端目前都不实现切换逻辑。

## 6. xj_jc 发送顺序与报文要点

### 6.1 周期轮询（非测试模式）

每 150 ms 由 `modbus_devices_poll()` 入队一项，共 **205 项**，一轮推进时间 **30750 ms**，实际发送受总线与队列影响。主站任务每 10 ms 执行一次，响应超时 200 ms。

- 第 1～200 项：40 组“传感器读取 → MT80 读取 → 整机推出状态 → 立杆状态 → 太阳板状态”。三台电机分别用逻辑地址 0x11/0x12/0x13，以 FC03 读取 2015（0x07DF）起 1 个寄存器。传感器在三合一（逻辑地址 2，FC03，500 起读 14 个寄存器）和水浸（地址 4，FC03，0 起读 1 个）之间轮换，首组为三合一。
- 第 201～204 项：独立 UART3 上的空调测量、湿度、控制参数、状态读取，沿用原地址与长度。
- 第 205 项：触发 B4 最新故障快照补发，无应答。

**编码规则**：用户补充说明已明确 L/H 低字在前、高字在后及负数补码。MT80 共 81 个逻辑量、107 个 16 位寄存器；18 个双字量在同一请求内读取并组合，其中电池电流按 I32/100，其余功率/电量按 U32/100；7 个温度量按 I16/100。四组定时时刻按秒/分/时三寄存器完整读取，缓存为当天累计秒数并开放写入。设备 `online` 表示最近事务状态，逐点首次读取有效标记决定 104 品质；不同分段不保证同一采样时刻。

`9622/9623` 低温禁充/禁放允许 -40～+10℃；`9656～9659` 温度保护参数按 I16 编码范围接受，实际设备可进一步限制。六项温度设置已开放 FC10 和 104 遥调。`9624` 分/秒和 `9661/9662/966F` 小时/分钟仍按既定布局处理。时间字段补充见第 10.2 节。

顺序保证正常周期入队的 USART0 读取站号交替，含跨轮边界；队列淘汰、发送失败及显式插入后仍可能失去交替，不承诺完全隔离迟到响应。三台万融电机不参与轮询。

### 6.3 B4 故障通知发送时机

B4 不占轮询位的等待应答，发送路径是主站模块内的**优先槽**：`app_fault_update()` 发现 32 位故障整体变化 → 覆盖优先槽最新值并置 pending → 气象总线当前事务完成或超时后，先发送限位停止，再发 B4 优先槽，最后取普通队列；轮询第 205 项仅重复置 pending 做周期补发。WSE 调试命令用“真实故障 OR 模拟掩码”组帧。因此 B4 可能合并等待期间的多次变位，不是完整事件历史；最终一致性靠周期补发。

### 6.4 IEC104 上行发送规则（USART1，115200）

- **自发变位**：每 100 ms 比较遥信快照与上次成功上送基线，有变化发 `M_SP_NA_1, COT=spont`；窗口/队列满则保留基线下周期重试。必须在 STARTDT 之后。
- **总召**：当前固件为 75 遥信、108 遥测（含参数回读），每帧最多 16 对象，完整总召需 14 个 I 帧，超过 k=12。主站应持续用 N(R) 确认；固件已保存快照与未发送进度，窗口/队列恢复后由通信任务续发；总召期间暂缓自发遥信，STOPDT 清理进度。
- **遥调准入**：处理当前 I 帧的有效确认并计入接收待确认数后，要求发送未确认数 <10、接收待确认数 ≤8、数据传输已启动且完整应答可入队。否则不执行、不发业务应答并清除空调/供电/环境校准全部预置；不缓存请求或应答，恢复后须重新预置。APCI 确认和周期 S 帧正常进行，k=12、w=8 不变。检查至写入提交和应答入队均在同一主循环调用中完成，无其他 104 发送者插入；若将来引入并发发送，需要改为预留应答空间。

- **确认与保活**：收满 w=8 帧主站 I 帧立即发 S 帧；数据传输态每 t2=10 s 周期发一帧 S 帧（串口承载工程扩展，代替 TCP 断链可观测）；链路空闲 t3=20 s 发 TESTFR ACT，t1=15 s 内等 TESTFR CON。
- 三合一上报沿用温度 `0x002000`、湿度 `0x002001`、风速 `0x002010`、风向 `0x002011`；从 505/504/500/503 寄存器得到 ℃、%RH、m/s、度。温度补码 `FF9B` 为 -10.1℃，湿度 `0292` 为 65.8%RH。
- 雨量 `0x002031` 改为 513 寄存器的雨量值（mm），不推断统计周期或降雨速率。旧翻斗计数、雨滴动态、雨水状态点已删除，不参加总召。
- 气象在线点 `0x001000` 统一反映设备已采集且最近事务在线的状态，水浸独立。应用直接读取三合一十倍原码，删除旧百分单位换算；湿度 >100%RH、风向 >360° 或档位 >7 时对应测量组标故障，首次读数前保持无效。
- 104 已删除七个旧遥测占位及重复的风/雨在线点、无来源的雨量故障点。V3.3 已定义风力/风向档位 `0x002012/0x002013`、风速/雨量调零 `0x000240/0x000241`、风向偏移/雨量灵敏度 `0x003011/0x003012`，上述新增点的 104 入口均已接入。
- MT80 的 V3.3 已实现 42 遥信、81 遥测、45 遥调、10 遥控。功率、电量、带符号电流及温度按完整数值和倍率上送；4 项定时时刻以当天累计秒数上送，采用 UINT32_LE 遥调。已加入寄存器/线圈首次读取有效标记，避免未读初值被当作正常数据。
- 对外编码、品质位、收发机制及完整点表见 [IEC104 通信协议](../xj_jc/iec104_protocol_spec.md)；底层适配见本文第 10 章。

### 10.2 MT80 数据编码与定时时刻补充

用户于 2026-10-14 提供补充图片第 5、6 条，明确 32 位数据的 L/H 组合及负数补码规则。图片中的 3002/3003、3022 是编码示例，实际地址和倍率仍按 MT80 当前表。

- 组合：`raw32 = L | (H << 16)`，H 地址为 L+1。单寄存器内部字节大端，寄存器间低字在前。
- 有符号量：16 位负数为 `raw16 - 65536`；32 位负数为 `raw32 - 4294967296`。电池电流先合并双字，再按 bit31 判断正负；温度按 bit15。
- 图片例 `L=93E0、H=0004` 得 300000，除以 100 为 3000。`FFF9` 为 -7；图片按 10 倍为 -0.7，本表温度按 100 倍为 -0.07℃。
- 电池电流 `3581/3582`：`L=FF9B、H=FFFF` 得 -1.01 A；H=0 时为 +654.35 A。不得仅按低字判断符号。

### 10.4 控制映射与联调约束

- MT80 36 个独立状态位的掩码为 3523/0FFF、3559/3FD1、3564/0FF3、3589/8700。充电状态 D1 及非 LED 型 D5 不建点；多位枚举保留在状态字。
- MT80 线圈写采用 FC05：置 1 写 FF00、置 0 写 0000；原表只给逻辑值，线码与自清时序需实机确认。三台万融使用 FC06/07D0，0/1/2=停止/正转/反转；新增 FC03/07DF 输入读取，物理按键优先限位停止规则见第 5.2 节。地址换算、输入极性和机构方向需联调核对。
- MT80 参数连续段 FC10 写入，每段最多 16 字；不连续地址分别提交，不跨空洞和拒写点。两项三合一校准参数各用 FC06。
- 三合一只使用 500～505、513；506～512、514～515 的可选测量不进入 104 点表。参数无读回定义，不以写回显替代测量。
- 遥控 ACTTERM 在提交设备请求前确认接受，遥调 ACTTERM 在写请求入队后返回；普通队列满时可能淘汰最旧请求，多段提交失败不能撤回已入队部分。设备异常/超时不追加 104 操作结果点。
