# 工程结构与运行机制

本工程运行于 GD32F10x，控制门、停机坪、普通照明、门加热解冻输出和 WS2812 灯效；同时通过
IEC 104 与上位机通讯，并以 Modbus RTU 轮询 RS-485 子设备。公开接口的职责和
状态字段含义写在各模块 `.h` 文件中；本文只说明模块关系和运行流程。

USART0 万融三路电机通信已实现。2026-10-14 起太阳能设备协议改为 MT80，独立温湿度/风/雨整合为三合一设备；路由、轮询、协议补充及分发板适配状态见 [系统通信与设计整理](../../docs/系统通信与设计整理.md)。

门、平台两种模式的功能与验收要求见 [门平台测试模式需求说明](门平台测试模式需求说明.md)，包含动作、互锁、暂停／继续、意图保留、停机及104行为对比。

## 启动顺序

`Core/main.c` 按以下顺序初始化，所有硬件和模块初始化均在 OS 主循环开始前完成：

```text
board_time_init
  -> debug_console_init
  -> iec104_port_init
  -> ws2812_driver_init / aux_output_init
  -> modbus_master_init / key_init
  -> motor_control_init
  -> iec104_server_init
  -> os_init
  -> usr_time_task_init / usr_event_task_init
  -> os_main_loop
```

`os_main_loop()` 固定按“定时任务 -> 软事件 -> 队列任务”的顺序运行。中断只处理
外设事件和 DMA 字节搬运；协议解析、业务控制及状态上报均在主循环上下文执行。

## 周期任务

`USER/APP/tasks/app_timer_task.c` 注册各任务，默认周期如下。

| 周期 | 工作内容 |
|------|----------|
| 10 ms | `modbus_master_task()`：RS-485 请求发送、响应解析与超时维护。 |
| 150 ms | `modbus_devices_poll()`：入队下一项 RS-485 巡检请求，单条请求响应超时为 200 ms。 |
| 10 ms | `iec104_server_comm_task()`：IEC104 收帧、解析、发送和协议定时器。 |
| 100 ms | `iec104_server_report_task()`：检测变位并组装主动上送报文。 |
| 50 ms | `key_scan_task()`：按键扫描、去抖和按键事件生成。 |
| 10 ms | 读取物理急停并更新门控，调用 `motor_control_update()`。 |
| 10 ms | 独立故障任务调用 `app_fault_update()`，汇总当前故障。 |
| 50 ms | `ws2812_app_update()`：根据门/平台状态推进灯效。 |

`usr_time_task_init()` 在按键、电机及 OS 初始化后先读取一次物理急停，再注册周期任务。
物理急停由运动任务直接检查，不等待 50 ms 按键扫描或软事件处理；释放后不自动恢复运动。

软事件在 `USER/APP/tasks/app_event_task.c` 注册。按键和门/平台灯效状态由软事件
处理，原急停/恢复事件入口保留；RS-485 写操作也经软事件转入各设备的 Modbus 写接口，避免在 IEC104 解析链路中
直接进行串口发送。

## 故障汇总与优先级

`USER/APP/app_fault.h/.c` 将现有输入和模块故障汇总为 32 位 `app_fault_u`，启动注册任务前采集一次，之后由独立故障任务按 `APP_FAULT_PERIOD_MS`（默认 10 ms）刷新。
故障任务调度优先级为 12；同轮到期时，在电机任务（2）、Modbus 通信任务（10）之后、常规 IEC104 上报任务（15）之前执行。
`bits` 查询单项故障，`levels.p1/p2/p3` 查询某一级是否有故障，`raw` 查询整体；三种视图共用同一份存储。

| 优先级 | 位范围 | 内容 |
| --- | --- | --- |
| P1 紧急安全 | 0～3 | 急停、门限位冲突、平台限位冲突、有效水浸告警。 |
| P2 运行告警 | 4～11 | 门/平台启动接口失败；空调高温、低温、湿度高、冷凝器高压、蒸发器冻结、制冷告警。 |
| P3 监测失效 | 12～24 | 5 台 Modbus 设备离线；温湿度、风速风向、水浸、雨量数据故障；空调 4 项传感器故障。 |

`app_fault_get()` 返回上次采集快照，`app_fault_highest_priority(faults)` 返回最高优先级；多项同时存在时保留全部故障位。
故障不锁存，随来源状态恢复而清除。设备上电尚未通信也归入 P3 离线；不将 IEC104 会话状态、CRC 错误或队列诊断单独列为整机故障。
水浸只有在线且数据合法时才置 P1；数据非法或离线时用 P3 表示无法确定，不能将缓存的“有水/无水”当作当前确认结果。
空调离线时只收集离线，不将缓存告警继续作为当前有效告警；在线后的分项状态沿用设备缓存，随后续轮询刷新。
P1 同时用于 WS2812 安全灯语；P2/P3 仅供查询，不触发灯光覆盖。不新增停机联动或 IEC104 点位，既有限位、急停保护保持原有行为。

```c
app_fault_u faults = app_fault_get();
app_fault_priority_e priority = app_fault_highest_priority(faults);
/* faults.bits.water_detected：有效水浸；faults.levels.p1 != 0U：存在 P1 故障。 */
```

## IEC104 数据流

全部 IEC104 协议基础、收发机制、点表、数值编码及报文示例统一维护在 [IEC104 通信协议](../iec104_protocol_spec.md)（V3.4，文档修订 R1）。接口按机巢机构、环境监测、空调和供电系统组织，包含 76 遥信、108 遥测、60 遥调、33 遥控；总召按每帧 16 对象发送，窗口/队列满后续发，遥信末帧12点。底层设备映射、资料缺项和联调配置见 [系统通信与设计整理](../../docs/系统通信与设计整理.md)。

遥调在发送未确认数 <10、接收待确认数 ≤8 且完整应答可入队时才处理。否则静默丢弃本次遥调并清空所有类别预置，不提交写入、不暂存应答；会话层仍正常确认 I 帧。上位机恢复通信后须重新预置，规则见协议第 3.6 节。

IEC104 模块位于 `USER/COMM/iec104/`，分层关系为：

```text
port -> iec104_server -> core -> app -> 控制模块 / Modbus 数据
```

- `port/` 负责串口 DMA 和接收 FIFO；一个串行数据块可以包含半帧或多个 APDU。
- `iec104_server` 是门面层。通信任务持续从 FIFO 取完整 APDU，半帧保留到下一周期；
  解析后的帧交给会话层，待发 APDU 再由该层取出并启动 DMA 发送。
- `core/` 包含 APCI/ASDU 编解码、会话序号窗口、确认、U 帧与定时器，以及 APDU 发送队列。
- `app/` 将 ASDU 绑定到本机点表：下行遥控进入门机或普通灯控制；总召唤和主动上送从
  电机、辅助输出（灯光、门加热解冻）、WS2812 和 Modbus 子设备快照采集数据。

接收链路如下：

```text
USART RX / DMA
  -> port 接收 FIFO
  -> iec104_server_comm_task
  -> APDU 解码
  -> iec104_session_handle_frame
  -> iec104_dispatch_handle
  -> iec104_app 的点表与业务动作
```

发送链路如下：

```text
主动变位或命令确认
  -> app / dispatch 组装 ASDU
  -> session 生成 I/S/U APDU 并入 txq
  -> iec104_server_comm_task
  -> port TX DMA
```

本工程使用串行字节流承载 IEC104 APDU。串行会话的 `STOPDT ACT` 是项目定义的逻辑
会话复位边界，详细报文和点表见 [IEC104 协议规范](../iec104_protocol_spec.md)。

## RS-485 Modbus 数据流

`USER/COMM/modbus/` 按设备业务、主站事务和设备协议分工。查看某个设备的协议时，
直接进入 `devices/modbus_<型号>.h/.c`；这些文件不访问队列、串口或全局缓存。

| 要查看的内容 | 文件与入口 |
| --- | --- |
| 轮询顺序、响应分发、在线状态与缓存 | `modbus_devices.c`：`modbus_devices_poll()`、`modbus_devices_parse_response()` |
| 业务异步写入、缓存读取 | `modbus_devices.h`：`modbus_*_queue_write*()`、`modbus_*_get*()` |
| 单条总线的发送、等待响应与超时 | `modbus_master.c`：`modbus_master_task()` |
| USART/DMA/GPIO 初始化与缓冲注册 | `modbus_port.c`：`modbus_port_open()` |
| 待发帧、总线路由与期望响应 | `modbus_txq.c/.h` |
| 设备组帧、寄存器含义与响应解析 | `devices/modbus_<型号>.c/.h`：`build_*()`、`parse_*()` |
| CRC、字节序和标准 RTU 帧格式 | `modbus_rtu.c/.h` |
| 从机地址、缓冲容量和任务时序 | `modbus_config.h` |

```text
轮询 / 业务写入（modbus_devices）
  -> 设备 build_*：校验参数、换算地址、生成请求帧
  -> modbus_txq：复制帧并保存路由、期望响应
  -> modbus_master：每条总线分别发送、等待、处理超时
  -> com_link：DMA/FIFO/485 方向控制
  -> modbus_master：取出匹配的响应
  -> modbus_devices：选择设备 parse_*，更新缓存与在线状态
  -> IEC104：通过 get 接口采集缓存
```

`build_*` 返回帧长，失败返回 0；`parse_*` 校验并更新调用方传入的数据。
`queue_write*` 返回 true 只表示请求已入队；实际通信结果在后续响应处理中更新。
气象设备 `get` 的返回值表示缓存复制成功，在线状态查看 `status.online`；空调整体
`get` 返回在线状态，参数和状态分段 `get` 返回对应有效标记。这些返回约定沿用现有行为。

每 150 ms 推进一项：40 组“三合一/水浸交替读取 → MT80 分段读取 → 整机推出状态 → 立杆状态 → 太阳板状态”，随后空调 4 项、B4 补发 1 项。
共 205 项，一轮推进 30750 ms；实际刷新还受总线及排队影响，不能用来保证分段新鲜度。
周期入队的 USART0 读取站号交替；队列淘汰和显式请求插入后不保证严格交替或彻底排除迟到响应。
三台万融电机使用 `4x-2000`（FC06/0x07D0）写命令，周期读取 `4x-2015`（FC03/0x07DF/1）物理输入；上行地址为 `0x11/0x12/0x13`，MT80 沿用 `0x14`。
bit0/1/2/3 分别为 CW 按键/CW 限位/CCW 按键/CCW 限位，按 1=有效。物理按键最高优先级：有效时取消旧通讯方向、清除待发运动，拒绝新的通讯启动；按键与对应限位同时有效则优先发送停止。无按键时依据最近已发送通讯方向处理对应限位，允许反向退出。同方向限位阻止通讯启动，停止回显后清除通讯方向。重复有效状态仍满足停止条件时会再次请求停止。
限位停止独立于普通队列，发送优先级为“限位停止 → B4 → 普通队列”，接口暂拒绝时保留，已在途事务不打断。状态读取通常每台 750 ms 入队，跨轮尾部间隔约 1500 ms，实际取决于总线与队列；失败保留旧缓存，首次有效读取前不拦截启动。完整位表、适用边界见 [系统通信与设计整理第 5.2 节](../../docs/系统通信与设计整理.md#52-万融电机命令与物理输入)。
`modbus_mt80.*` 支持 `01/03/04/05/10`，周期读取全部 81 个逻辑量（107 个寄存器）、5 个线圈并记录各自首次采集有效性。每次最多 16 寄存器，32 位 L/H 必须同帧完整读取；电池电流、温度按补码和 100 倍换算，六项温度设置已开放；四组定时时刻按秒/分/时三寄存器整组读写，缓存及 104 回读为当天累计秒数，104 遥调采用 UINT32_LE，范围 0～86399。
三合一读取逻辑地址 2、FC03、500 起 14 个寄存器；温度按 int16 补码解码。旧三路独立驱动、getter、写事件及工程引用均已删除，应用直接读取三合一缓存；XM8537 水浸保留独立协议；新校准使用 `modbus_weather_sensor_queue_write()`。
主控侧保持 9600；wether 下游三合一口已为 4800，sun_control/master 的 MT80 下游地址已为 0x0A。万融 FC03 状态读取及 FC06 停止沿用现有透明转发，无需修改分发板。
主站每 10 ms 执行一次，USART0 和空调总线的单条请求响应超时均为 200 ms。两条总线独立等待响应，共享发送队列；
队列满时淘汰最早的旧请求，帧缓冲覆盖时淘汰被覆盖请求。

### weather 板 B4 故障同步

weather 板地址为 `0xB4`，接收单向状态通知，不返回应答；以下是双方约定的 RTU 格式扩展，不是标准读写寄存器事务。
功能码 `0x41` 取自 Modbus 用户自定义范围；所有多字节故障数据按 GD32 小端内存顺序发送，CRC 仍为标准 Modbus CRC16。

```text
B4 41 04 D0 D1 D2 D3 CRC低 CRC高
          └─ fault_state.raw 的四字节内存副本，D0 为最低字节
```

整帧 9 字节，CRC 覆盖前 7 字节。组帧接口为 `devices/modbus_weather.c` 的 `modbus_weather_build_fault_notification()`。
使用 `memcpy` 复制 uint32_t，接收端也应复制到对齐的变量，避免将帧的第 3 字节地址直接强转为 uint32_t 指针。
该内存复制约定适用于小端收发端；迁移到大端平台时需显式转换。已知报文示例：

```text
全部恢复：  B4 41 04 00 00 00 00 11 DA
仅急停：    B4 41 04 01 00 00 00 10 26
字节序示例：B4 41 04 78 56 34 12 7F A7  （数值 0x12345678，仅验证字节序）
```

故障位定义与 `APP/app_fault.h` 固定一致，后续不得重排：

| bit | 含义 |
| --- | --- |
| 0 | 急停 |
| 1 / 2 | 门限位冲突 / 平台限位冲突 |
| 3 | 有效水浸 |
| 4 / 5 | 门启动接口失败 / 平台启动接口失败 |
| 6 / 7 / 8 | 空调高温 / 低温 / 湿度高 |
| 9 / 10 / 11 | 空调冷凝器高压 / 蒸发器冻结 / 制冷告警 |
| 12 / 13 / 14 / 15 / 16 | 温湿度 / 风速风向 / 水浸 / 雨量 / 空调离线 |
| 17 / 18 / 19 / 20 | 温湿度 / 风速风向 / 水浸 / 雨量传感器数据故障 |
| 21 / 22 / 23 / 24 | 空调机柜温度 / 蒸发器 / 冷凝器 / 湿度传感器故障 |
| 25～31 | 保留，发送端置零 |

四字节包含全部 P1/P2/P3 状态，不包含灯光应用的水浸保持状态。接收端只有在 bit14 和 bit19 均为 0 时，才能将 bit3=0 解释为有效无水。

`app_fault_update()` 发现完整状态变化后，通过 `modbus_master_queue_weather_fault()` 覆盖最新待发值并置 pending；稳定采样不重复触发。
轮询 B4 项调用 `modbus_master_repeat_weather_fault()`，仅置同一个 pending，补发最新已发布状态，不向普通队列插入重复报文。
WSE 调试通过 `modbus_master_set_weather_fault_debug()` 更新独立模拟掩码；组帧使用“真实故障值 OR 模拟掩码”，周期补发也保持模拟位。
真实状态更新不会覆盖调试掩码，调试切换不会清除真实故障；`WSE:0` 清除掩码并请求发送真实值。模拟位仅影响 B4 报文，不写入本机 `fault_state`。
优先槽位于主站模块，由原 10 ms 主站任务处理，不注册新 OS 任务，也不使用事件或队列任务槽。

气象总线当前事务完成或超时后，先处理优先槽，再从普通队列取请求；空调总线独立运行。
组帧或启动发送失败时保留 pending 和普通队列，成功启动后消费 pending；DMA 发送期间的新状态只修改优先槽，不修改在途帧。
B4 不进入等待应答状态、不触发应答超时、不维护 B4 在线位。底层仍等待 DMA/USART 发送完成并恢复收发方向后，才允许下一帧。
优先槽保存最新状态，可能合并等待期间的多次变位，不能作为完整事件历史；无应答只能确认本机已发送，周期补发用于最终同步。

## 门、平台与辅助输出控制链路

电机控制分为两层：

```text
按键或 IEC104 遥控
  -> motor_control：门/平台命令、互锁顺序、换向等待、到位停机、急停和故障
  -> motor_driver：单台电机的正反向 PWM、停止和刹车
```

`motor_control` 通过板级接口读取四个限位并控制电吸锁，门的两台电机共用一组位置反馈。
常规模式关门前先收回平台，平台伸出前先开门；反向切换保留 100 ms 等待。门关到位后吸锁，开门前释放。
门与平台各自使用明确的内部状态机，定时任务仅调用一次 `motor_control_update()`。

按键短按采用“启动 → 暂停 → 继续”：当前流程发起键的短按暂停门和平台全部输出，保留两个状态机及换向等待；再次短按按当前模式检查运行条件后继续。另一个按键在运行或暂停期间均可提交新目标，替换冲突意图并成为新的发起键；兼容的当前动作继续，需要反向时先停止并等待 100 ms。无操作意图且处于中间位置时，门默认关门、平台默认收回；上电不自动运动。短按识别仍在松键时产生，按下时长 >100 ms 且 <2000 ms，扫描周期 50 ms。

常规模式的位置互锁为“平台收回到位才关门、门打开到位才伸平台”，对按键、104 和内部联动统一生效。启动、恢复及实际运行持续检查；运行中所需到位信号丢失，立即停止整套流程并清除意图，不因信号恢复而自动重启。暂停期间位置变化时保持停止，恢复操作会重新安排必要的开门/收平台步骤。急停、限位冲突和连续三次启动接口失败同样取消整套流程；意图只保存在 RAM 中。

测试模式通过104遥控 `0x000250` 进入、`0x000251` 退出，均先选择再执行；`0x000019` 上报当前模式（1=测试，0=常规）。测试模式开门就直接开到位，关门就直接关到位，平台伸／收也直接到各自限位，不自动操作或等待另一机构。自身到位停机、整套暂停／继续、急停、限位冲突、启动失败处理和100 ms换向等待保留；暂停恢复直接回到原方向，不补做联动。实际切换先停止全部输出并清除意图、等待、暂停和按键占用；重复设置当前模式无动作。上电默认常规模式，模式不跨断电保存。

两种模式下，按键流程在运行、联动等待、换向等待及暂停期间，104 门/平台四个遥控点禁止接管：选择返回否定 ACTCON（0x47），执行返回否定 ACTTERM（0x4A），并清除待执行选择；执行前再次检查权限。模式切换点允许处理，实际切换会终止旧流程。其他遥控点正常处理。流程完成或终止后解除限制。暂停时现有运行遥信为 0；本轮未增加独立的“暂停/按键占用/互锁丢失”104 点位。
`motor_control_status_t` 分别给出位置、实际动作、故障、按键控制／暂停状态和测试模式，状态读取仅复制快照；IEC104 不访问驱动方向。
`motor_driver` 对每台电机管理两个方向通道，运行时只使能一个，停止时全部关闭，刹车时同时使能。

实际到位判断使用光电限位开关，四个输入均为上拉输入、低电平有效：

| 引脚 | 到位含义 |
|------|----------|
| PB12 | 平台伸出到位 |
| PB13 | 平台收回到位 |
| PB14 | 门关闭到位，两台门电机共用 |
| PB15 | 门打开到位，两台门电机共用 |

启动阻止、运动停机、门/平台状态和反馈快照均使用这四个输入。旧 PA4/PA5、PC6～PC9
不再作为电机到位依据。目标到位后在运动更新中停止对应电机；门到位时两台门电机一起停止。

PB12/PB13 或 PB14/PB15 同时读低视为限位冲突。上电、每次运动更新（默认 10 ms，含空闲期）
及业务命令入口均检查；任一组冲突立即关闭平台和两台门电机输出，取消两轴运动及联动/换向等待。
限位恢复正常后自动清除对应故障，只刷新位置状态，必须收到新命令才可再次运动。
故障出现或清除时，运动周期任务立即触发现有 IEC104 变位上报；常规报告任务保留发送失败重试。
新增遥信 `0x000017` 为门限位冲突、`0x000018` 为平台限位冲突，1=故障、0=正常；
总召也包含这两个点，对应机构的原状态码在故障时为 3。

`aux_output` 控制 PC3 指示灯、PC4 内部照明和 PC5 门加热解冻伴热带。PC5 低电平导通，
上电默认关闭；软件通过 `aux_output_enable_door_heater()` / `aux_output_disable_door_heater()`
控制供电，用于门加热解冻；恒温由伴热带自身实现。WS2812 由 SPI/DMA 输出，由门和平台状态
驱动灯效；当前仅通过 IEC104 遥信上报灯效是否活动，不提供 WS2812 遥控点。
内部照明遥控为 `0x000222` 开启、`0x000223` 关闭；门加热遥控为 `0x000224` 使能、
`0x000225` 关闭，均沿用选择后执行流程。两路状态分别通过遥信 `0x000015`、`0x000016` 上报。

### P1 安全灯语

`ws2812_app_update()` 每 50 ms 读取 `app_fault_get()`，显示顺序为 P1 灯语 > WSE 调试 > 门/平台业务。
P1 内固定按急停 > 门/平台限位冲突 > 水浸选择；P2/P3 本次不接入灯语。

| P1 状态 | 整条灯带效果 |
| --- | --- |
| 急停 | 纯红常亮。 |
| 门或平台限位冲突 | 红色双闪：亮 150 ms、灭 150 ms、亮 150 ms、灭 1050 ms，周期 1500 ms。 |
| 有效水浸 | 两半红色交替，每 500 ms 换边，不全灭。奇数灯珠前半多一颗，单颗时保持红色常亮。 |

更高显示优先级在下次灯光刷新立即生效，并从新效果起点播放；降级或恢复需候选状态持续稳定 2 秒，期间继续显示原告警。
首次观察到恢复时开始计时；故障再次出现会取消恢复等待。告警覆盖期间业务和调试动画暂停推进，但输入/调试选择仍可更新，退出后继续当前选择。
已经采集到有效水浸后，离线或非法数据会保持水浸灯语，直到取得在线且合法的无水状态后才进入恢复等待；该保持仅存在灯光应用内，不修改故障联合体。
故障状态选择与恢复计时属于应用层；双闪、两半交替画面位于 `effects/ws2812_basic.c`，常亮复用帧填充接口。
闪烁灭灯阶段仍视为灯效活动。P1 覆盖不依赖 DEBUG 编译开关，也不改变电机保护或水浸的控制联动。

### WSE 灯效调试

本机灯带按 BRG（蓝、红、绿）顺序发送颜色字节，每字节高位先发；上层颜色接口仍使用 RGB。

USART2 处于 DEBUG 角色时，发送以下命令并以回车或换行结束。调试灯效覆盖整条 WS2812，
每次收到有效 WSE 命令都会重置播放进度，重复发送同一编号也会从头播放；P1 显示期间只保存选择，待告警显示退出后播放。
每次有效命令同时更新 B4 优先槽（重复命令也请求发送），在气象总线当前事务结束后下发对应模拟故障状态。

| 命令 | 灯效 | B4 模拟掩码 |
| --- | --- | --- |
| `WSE:0` | 退出调试覆盖，恢复当前门/平台业务灯效 | 0，仅同步真实故障 |
| `WSE:1` | 急停灯语：整条纯红常亮 | `0x00000001`，bit0 急停 |
| `WSE:2` | 限位冲突灯语：红色亮 150 ms、灭 150 ms、亮 150 ms、灭 1050 ms | `0x00000002`，bit1 门限位冲突，不模拟平台位 |
| `WSE:3` | 水浸灯语：两半红色交替，每 500 ms 换边 | `0x00000008`，bit3 水浸 |

时序基于现有 50 ms 灯效任务，复用真实 P1 灯语的画面接口。调试演示灯光并向 B4 同步模拟位，不置本机故障位，不触发本机停机或水浸保持逻辑。
真实 P1/P2/P3 位完整保留在报文内，模拟位持续到 `WSE:0`；例如水浸传感器离线期间调试水浸，报文可同时包含真实离线位和模拟水浸位。
编号超出 0～3 或命令格式错误时保持当前选择。真实 P1 告警始终优先于调试；无真实告警覆盖时，切换编号或 `WSE:0` 在下一次刷新生效，不经过 2 秒恢复等待。
业务输入在调试期间仍可更新，`WSE:0` 后重新参与灯效输出。当前保留 12 颗灯珠配置。
原六种机械科幻效果继续保留在灯效库中，下面的动态预览展示该库的六种效果，不对应当前 WSE 编号。

[打开动态预览](ws2812_preview.html)：使用实际 C 灯效库输出的 24 秒帧序列，支持暂停、拖动时间和调速。
修改灯效后运行 `python3 tests/preview_ws2812.py` 更新预览；屏幕亮度和光晕仅作示意。

WS2812 按以下职责划分，公共类型和灯效库不包含 MCU、板级或调试头文件。

```text
USER/
├── APP/
│   └── ws2812_app.c/.h                  # 门/平台灯效、调试覆盖、统一运行状态、周期提交
└── CONTROL/ws2812/
    ├── ws2812_types.h                  # RGB 帧、闪烁/拖尾/波浪/呼吸状态类型
    ├── ws2812_frame.c/.h                # RGB 帧清空、区间填色（含跨尾部区间）
    ├── effects/
    │   ├── ws2812_basic.c/.h            # 基础绘制、原六种基础效果
    │   └── ws2812_mechanical.c/.h       # 六种机械科幻效果
    └── driver/
        └── ws2812_driver.c/.h          # BRG 编码、SPI/DMA、完成中断
```

应用中的 `ws2812_app_state_t` 集中持有门/平台输入、业务动画状态、调试播放时间、活动状态与 RGB 帧。
调试编号继续由 `debug_ctrl.bits.wse` 保存，避免两处保存选择结果。
驱动私有 `ws2812_driver_state_t` 只持有 DMA 发送缓冲及传输标志，不包含业务状态。
帧由调用者分配；`ws2812_frame_t` 描述颜色数组和灯珠数量，数组元素统一使用 `0xRRGGBB`。

应用每 50 ms 清空 RGB 帧，按原顺序绘制门/平台或调试效果，最后调用一次 `ws2812_driver_submit()`。
驱动检查 DMA 空闲并收尾已完成的传输后，再编码到独立的发送缓冲并启动 DMA。
DMA 忙时返回 false，不改写正在发送的数据，不增加排队或重试；调用返回后应用可复用 RGB 帧。
原先上层显式复制、驱动再次复制的流程已合并，应用不再操作 DMA 缓冲。

六种新效果接口保留原名称，首参数改为 `ws2812_frame_t *`，第二参数为播放时间（ms）。
基础动画需要的状态由调用者持有并传入；不再在灯效库内保存按灯带编号索引的呼吸状态。
所有基础绘制和原六种效果均保留，原六种通过 `ws2812_render_basic_effect(&frame, effect, elapsed_ms)` 调用。
例如以下代码只绘制 RGB 帧，不访问硬件：

```c
uint32_t pixels[12] = {0};
ws2812_frame_t frame = { .pixels = pixels, .led_count = 12U };
ws2812_effect_reactor_heartbeat(&frame, 350U);
```

驱动初始化为 `ws2812_driver_init()`，完成中断入口为 `ws2812_driver_dma_irq()`。
业务层使用 `ws2812_app_set_door_state()`、`ws2812_app_set_platform_state()` 更新输入，
通过 `ws2812_app_select_debug()` 切换调试效果；`ws2812_app_is_active()` 供 IEC104 采集活动状态。

机械科幻灯效的可调参数集中在 `effects/ws2812_mechanical.c` 各函数开头：

| 参数后缀或名称 | 含义与调整方式 |
| --- | --- |
| `_ms` | 毫秒。旋转调 `rotation_ms`；扫描分别调 `traverse_ms` 和 `endpoint_hold_ms`，往返周期自动推导 |
| `_pos` | 归一化空间单位。通常 256 单位表示整条线性灯带、一圈或中心到端点；等离子效果一圈为 512 单位，函数内有说明 |
| `*_width_pos` | 光层宽度；对称光晕为中心到边缘的半宽，转子拖尾为从头部向后的长度 |
| `_level` / `_percent` | 0～255 亮度值 / 百分比；心跳的 `edge_level_percent=20` 表示端点保留中心脉冲强度的 20% |
| `_color` | 明确标注用途的 RGB 配色，例如 `idle_color`、`pulse_color`、`release_color` |

`POSITION_SPAN=256`、`RGB_MAX=255` 是固定计算尺度和颜色格式范围，不跟随灯珠数改变。
平滑扫描的 `3`、`2` 来自 `x²(3−2x)` 插值公式，也不属于灯效调参项。
跃迁蓄能的阶段终点与总周期由各阶段持续时间相加得到，调整某阶段无需同步修改后续时间。

改变同一条灯带的灯珠数：修改 `driver/ws2812_driver.h` 的 `WS2812_STRIP0_LED_COUNT` 并重新编译；
应用和 DMA 缓冲随之调整，六种新效果按 `frame->led_count` 自动映射位置，保持周期和相对宽度。
例如 12 改 24 颗后，转子仍每 3.2 秒一圈，但每秒经过的灯珠更多；无需修改 `POSITION_SPAN`。
灯珠较少时空间效果会变粗，1～2 颗无法呈现完整扫描/拖尾。
门/平台业务灯效仍按既有物理区域使用前 8 颗、索引 8～9 等固定区间，变更布局时需单独调整
`APP/ws2812_app.c`；越界区间会被忽略。原基础白色拖尾仍固定 6 颗并按实际数量截短。
如果增加的是一条独立灯带，需要补充板级 SPI/DMA 映射、驱动配置及对应应用帧/状态，灯效算法仍可复用。

| 基础灯效枚举 | 保留的效果 |
| --- | --- |
| `WS2812_BASIC_WHITE_TRAILING` | 白色六颗拖尾，每 100 ms 前进一颗，头部亮度 80% |
| `WS2812_BASIC_GREEN_FLASH_THEN_STEADY` | 绿色亮 200 ms、灭 200 ms，三轮后常亮 |
| `WS2812_BASIC_YELLOW_STEADY` | 黄色常亮 |
| `WS2812_BASIC_RED_FLASH` | 红色亮 700 ms、灭 300 ms |
| `WS2812_BASIC_RED_STEADY` | 红色常亮 |
| `WS2812_BASIC_WHITE_BREATHING` | RGB 同步从 `0x000000` 渐亮至 `0xFFFFFF` 再渐暗，亮暗各 2 秒 |
