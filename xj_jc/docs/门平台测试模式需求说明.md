# 门、平台常规模式与测试模式需求说明

日期：2026-11-06。版本：需求 V1.2（软件实施版）。

现状基线：本地提交 `2b8b257`（完善门平台按键暂停续行及104控制互锁）。

本文描述测试模式及其与常规模式的差异。基线提交已具备常规联动、按键暂停／继续和意图保留功能；测试模式现已完成软件实现，尚未进行实机验证。完整点表见 [IEC104 通信协议 V3.4](../iec104_protocol_spec.md)，工程运行机制见 [工程说明](README.md)。

## 1. 需求结论与范围

通过 IEC104 遥控进入测试模式。测试模式的动作规则为：开门就直接开到位，关门就直接关到位；平台伸出就直接伸到位，收回就直接收到位。每条动作命令只控制对应机构，不等待或自动操作另一机构。

保留急停、各自到位停机，以及现有整套流程的按键暂停／继续和动作意图保留功能。

“取消联动”同时包含以下两项：

1. 关门不再自动收平台，平台伸出不再自动开门。
2. 关门不再要求平台收回到位，平台伸出不再要求门打开到位；启动、暂停恢复和运动过程中均不使用这两个跨机构位置条件阻止动作。

仅删除前置动作调用而仍等待另一机构到位，不满足测试模式需求。

本次范围为本机门组、平台及其 IEC104 命令。两台门电机仍作为一个门组共同控制；其他 Modbus 电机、空调、照明、门加热和灯效不增加测试控制功能。

## 2. 术语与停止含义

| 术语 | 含义 |
| --- | --- |
| 动作意图 | 已接受但尚未完成的目标，如关门、收平台，包括为完成目标而保留的运行、前置等待和换向等待阶段 |
| 发起键 | 当前按键流程的控制键，可能是门键或平台键；同一发起键负责整套流程暂停／继续 |
| 暂停 | 关闭门和平台全部电机输出，保留动作意图和状态机，等待人工继续 |
| 继续 | 由原发起键触发，按当前模式和最新输入重新安排原目标的执行 |
| 到位完成 | 对应机构达到自身目标限位，停止该机构并结束其动作请求 |
| 终止 | 关闭门和平台全部电机输出，清除动作意图、等待阶段、暂停状态和按键占用；不能通过继续操作恢复旧目标 |

暂停不等于终止。运行遥信为 0 只说明当前未运动，不能据此判断动作意图已经清除。

## 3. 两种模式差异总表

| 项目 | 常规模式 | 测试模式 |
| --- | --- | --- |
| 开门 | 直接开门，到开到位后停止 | 直接开门，到开到位后停止，不操作平台 |
| 关门 | 先收平台，确认平台收回到位后关门，到关到位后停止 | 直接关门，到关到位后停止，不操作平台 |
| 平台伸出 | 先开门，确认门打开到位后伸平台，到伸出到位后停止 | 直接伸出，到伸出到位后停止，不操作门 |
| 平台收回 | 直接收回，到收回到位后停止 | 直接收回，到收回到位后停止，不操作门 |
| 关门前的位置条件 | 平台收回到位，并满足现有平台状态条件 | 不检查平台位置和动作阶段作为关门前置条件 |
| 伸平台前的位置条件 | 门打开到位，并满足现有门状态条件 | 不检查门位置和动作阶段作为伸出前置条件 |
| 运行中的跨机构互锁 | 关门时平台收回到位信号丢失，或伸平台时门打开到位信号丢失，终止整套流程 | 不因上述跨机构位置条件不满足而停止 |
| 暂停后继续 | 重新检查互锁，必要时安排收平台或开门，再执行原目标 | 继续原目标，不自动安排另一机构的前置动作 |
| 单机构新目标对另一机构的影响 | 可以因正常联动改变另一机构的目标 | 不因位置互锁自动改变另一机构的目标；其已有请求可以保留 |
| 自身到位停机 | 保留 | 保留 |
| 按键整套暂停／继续 | 保留 | 保留，暂停范围仍包括门和平台 |
| 急停、限位冲突、启动失败 | 按现有规则停止并取消流程 | 保留现有处理 |
| 反向切换等待 | 100 ms | 100 ms |
| 两台门电机 | 门组共同控制 | 门组共同控制 |

测试模式的“分别测试”指方向命令不自动带动另一机构，不改变现有“暂停整套流程”的操作范围。

## 4. 常规模式控制策略

### 4.1 门

1. 开门请求直接驱动门组打开，不要求平台处于指定位置。
2. 关门请求保留“最终关门”的意图，先请求平台收回；平台尚未收回到位时，门保持等待。
3. 平台收回到位且符合现有启动条件后，门组开始关闭。
4. 实际关门过程中持续检查平台收回到位条件。该条件丢失时，停止门和平台全部输出，清除整套流程意图；信号恢复不自动重新关门。
5. 开门到开限位、关门到关限位后，两台门电机一起停止。

### 4.2 平台

1. 收回请求直接驱动平台收回，不要求门处于指定位置。
2. 伸出请求保留“最终伸出”的意图，先请求开门；门尚未打开到位时，平台保持等待。
3. 门打开到位且符合现有启动条件后，平台开始伸出。
4. 实际伸出过程中持续检查门打开到位条件。该条件丢失时，停止门和平台全部输出，清除整套流程意图；信号恢复不自动重新伸出。
5. 平台到伸出限位或收回限位后，停止对应运动。

### 4.3 暂停恢复示例

门键发起关门 → 平台正在收回 → 再按门键 → 门和平台全部暂停，保留最终关门及收平台阶段 → 再按门键 → 重新检查限位与互锁，必要时继续收平台 → 平台收回到位后关门 → 门关到位后结束。

暂停期间如果另一机构位置发生变化，保持暂停，不因到位信号恢复而自行启动。继续操作时根据最新位置重新安排必要的前置步骤。

## 5. 测试模式控制策略

| 命令 | 执行动作 | 停止条件 |
| --- | --- | --- |
| 开门 | 门组直接打开，不检查平台位置，不操作平台 | 门开到位，两台门电机一起停止 |
| 关门 | 门组直接关闭，不检查平台位置，不操作平台 | 门关到位，两台门电机一起停止 |
| 平台伸出 | 平台直接伸出，不检查门位置，不操作门 | 平台伸出到位后停止 |
| 平台收回 | 平台直接收回，不检查门位置，不操作门 | 平台收回到位后停止 |

目标已经到位时，不再向该方向启动。动作中仍可按原发起键暂停，再按继续原方向直到到位；恢复时也不追加另一机构的动作。急停和故障处理按第 7 节保留。

例如：平台未收回时发起关门，门直接关到位；中途暂停后再继续，仍直接关到位，平台不因关门请求动作。

## 6. 按键、暂停、继续与意图保留

本节除明确列出的恢复差异外，两种模式一致，沿用现有短按操作。长按不新增电机控制含义。

| 操作场景 | 两种模式共同规则 |
| --- | --- |
| 无有效流程时短按门键 | 门关闭到位则发起开门；门打开到位或处于中间位置则发起关门 |
| 无有效流程时短按平台键 | 平台收回到位则发起伸出；平台伸出到位或处于中间位置则发起收回 |
| 流程运行／等待／换向期间短按原发起键 | 暂停门和平台全部输出，保留原目标、两个状态机和已有换向等待进度 |
| 暂停期间无操作 | 一直保持暂停；换向等待不因暂停期间时间流逝而继续累计 |
| 暂停期间短按原发起键 | 按当前模式恢复原目标；恢复前重新检查急停、限位冲突和自身目标到位情况 |
| 运行或暂停期间短按另一个键 | 按该机构当前方向／阶段及位置规则提交新目标，并成为新的发起键；不是无条件暂停 |
| 新提交的目标要求对应机构反向 | 替换该机构的冲突目标；需要换向时先停机，再执行原有 100 ms 等待 |
| 两个机构的请求全部结束 | 释放按键流程占用；下一次短按按当时位置建立新请求 |

“另一个键”示例：门键发起的流程中按平台键，提交平台目标；平台键发起的流程中按门键，提交门目标。目标与已有动作冲突时按现有规则替换，兼容请求保留；常规模式继续遵守联动，测试模式不追加联动。

暂停后恢复的差异必须覆盖恢复入口本身：常规模式恢复关门可以重新请求收平台，恢复伸平台可以重新请求开门；测试模式恢复这两个方向时均不得追加上述请求。

暂停中若对应机构已经到达目标位置，继续操作后结束该请求，不再向目标方向启动电机。暂停、动作意图和发起键只保存在 RAM，不跨断电恢复。

## 7. 到位、故障与终止处理

| 事件 | 常规模式 | 测试模式 | 原意图处理 |
| --- | --- | --- | --- |
| 门达到自身目标限位 | 停止门组 | 相同 | 结束门请求；其他有效请求按各自规则处理 |
| 平台达到自身目标限位 | 停止平台 | 相同 | 结束平台请求；其他有效请求按各自规则处理 |
| 原发起键触发暂停 | 停止门和平台全部输出 | 相同 | 保留，等待继续 |
| 急停有效，包括暂停期间触发 | 停止门和平台全部输出，急停有效期间禁止运动 | 相同 | 清除；释放急停不续跑 |
| 门开、关限位同时有效 | 停止门和平台全部输出 | 相同 | 清除；故障恢复后需新命令 |
| 平台伸、收限位同时有效 | 停止门和平台全部输出 | 相同 | 清除；故障恢复后需新命令 |
| 连续三次启动接口失败 | 按现有处理终止整套流程；门组任一电机启动失败时先停止整个门组 | 相同 | 清除；后续新命令按现有规则重试 |
| 关门运动中平台收回到位信号丢失 | 终止整套流程 | 不因此停机 | 常规模式清除；测试模式保留并继续当前请求 |
| 平台伸出运动中门打开到位信号丢失 | 终止整套流程 | 不因此停机 | 常规模式清除；测试模式保留并继续当前请求 |
| 进入或退出测试模式 | 先终止整套流程，再切换模式 | 相同 | 清除；切换后需新动作命令 |
| 断电或重启 | 输出按上电初始化处理，不自动运动 | 重启后回到常规模式，不自动运动 | 全部丢弃 |

跨机构位置互锁取消，不表示忽略该机构的限位冲突。例如测试模式关门时，平台收回限位由有效变无效不影响关门；如果平台伸出和收回限位同时有效，仍停止全部电机。

门锁沿用现有行为：开门前释放，门关闭到位后吸锁。测试模式不新增单独的门锁控制命令。

## 8. 模式生命周期

1. 上电默认常规模式，不保存测试模式到非易失存储器，不自动恢复旧动作。
2. 进入测试模式必须通过 IEC104 模式命令完成选择与执行；仅选择不改变模式。
3. 实际从常规模式切换到测试模式时，先停止门和平台全部输出，清除原动作请求、前置等待、换向等待、暂停状态和按键占用，再进入测试模式。
4. 进入测试模式本身不发起开门、关门或平台动作，需要另发方向命令或操作本地按键。
5. 从测试模式退出时同样先终止当前流程，再恢复常规模式；不自动关门、收平台或补做原目标。
6. 急停和故障清除动作意图，不作为自动退出测试模式的条件。释放急停或故障恢复后，仍需新命令，运动继续遵守当时模式。
7. 模式切换不能让旧的已选择方向命令跨模式执行；切换时清除旧选择。新动作须在切换后重新选择和执行。
8. 重复设置当前模式仅确认，不停止当前动作、不清除当前意图；只有实际模式改变才终止旧流程。

模式切换命令与四个方向命令分别处理：即使存在按键流程，也允许按有效的模式切换命令先终止旧流程、再切换，避免因按键占用而无法退出测试模式。

## 9. IEC104 命令与反馈

### 9.1 复用现有方向点

| IOA | 命令 | 常规模式 | 测试模式 |
| --- | --- | --- | --- |
| `0x000200` | 请求开门 | 开门到位 | 直接开门到位 |
| `0x000201` | 请求关门 | 收平台后关门到位 | 直接关门到位 |
| `0x000210` | 请求平台伸出 | 开门后伸平台到位 | 直接伸平台到位 |
| `0x000211` | 请求平台收回 | 收平台到位 | 直接收平台到位 |

两种模式均使用既有 `C_SC_NA_1` 选择／执行流程：`SCO=0x81` 选择、`SCO=0x01` 执行。保留现有报文格式、地址、保留位、选择匹配及控制权校验；重复同方向遥控不改成暂停命令。

`SCS=0` 继续仅应答，不执行动作，不表示暂停、继续、停止或退出测试模式。ACTTERM 表示接受请求，不表示电机已经运动或机构已经到位。

### 9.2 新增模式点

| 类型 | 功能 | 语义 | IOA |
| --- | --- | --- | --- |
| 遥控 | 进入测试模式 | 完成选择／执行后切换，切换本身不启动运动 | `0x000250` |
| 遥控 | 退出测试模式 | 完成选择／执行后切换回常规模式 | `0x000251` |
| 遥信 | 测试模式有效 | 0=常规模式，1=测试模式；参与总召和变位上送 | `0x000019` |

协议 V3.4 已同步上述点位：76遥信、108遥测、33遥控、60遥调。总召仍为14个I帧，遥信末帧从11点增加到12点；主站需同步新增点位与遥信总数。

### 9.3 按键与104控制权

两种模式均保留按键流程优先规则：按键流程在运行、联动等待、换向等待或暂停期间，104 四个方向点不可接管。选择返回否定 ACTCON（`0x47`），执行返回否定 ACTTERM（`0x4A`），并清除待执行选择；被拒绝的方向命令不缓存、不补执行。流程完成或终止后解除占用。模式切换命令按第 8 节处理。

暂停／继续沿用本地发起键，不新增104暂停／继续／停止点。104 发起的动作没有本地发起键，首次短按某键仍按现有规则提交该机构目标，不能将其描述为直接暂停104动作。

### 9.4 状态真实性

两种模式下，到位、运行、急停、限位冲突和故障状态继续反映实际输入或已有控制快照，不因取消互锁而伪造“另一机构已到位”。保留现有暂停时运行遥信为 0 的表达；本轮不新增暂停、按键占用或互锁丢失遥信。

| 编号 | 场景 | 常规模式预期 | 测试模式预期 |
